# EMC Locus 0.22.1

Release date: 2026-07-31

## Purpose

This release closes two resource-preparation gaps. A station setup can now
describe what material is required independently from whether one physical
asset is currently usable, and LAB CONSOLE can record the authoritative
calibration event already owned by the metrology domain.

## Station Material Contract

The typed Rust core schema
`emc-locus.station-measurement-setup-definition.v3` separates:

- material requirements selected by category, stable capability, or exact
  physical asset;
- physical assignments with pinned asset/model revisions and physical-port
  mappings;
- contextual operational readiness for a date, laboratory location and
  execution mode.

Logical ports belong to requirements. Physical ports are resolved only after a
real asset is selected. The Local Agent is authoritative for category ancestry,
capability and range matching, trusted unit conversion, driver evidence, port
resolution and operational blockers.

An exact asset may be imposed while blocked. This records a design constraint,
not an assignment, readiness verdict or safety override. No substitution is
made silently. `qualified` means that the logical definition is coherent;
`ready` additionally requires every mandatory physical assignment and every
service, availability, location, reservation, metrology and correction check.

Planned-test preparation resolves deferred roles and intersects station and
method requirements. The resulting assignment snapshots the authoritative
asset identity, immutable model reference and selected ports.

## Calibration Workflow

LAB CONSOLE now provides **Enregistrer un étalonnage**, a dedicated form and a
readable calibration history. The command persists the global decision, dates,
certificate, provider, as-found/as-left states, adjustment, uncertainty,
traceability, comment and content-addressed proof document through the existing
metrology service.

The evidence boundary remains explicit:

1. a calibration event determines global metrology status and validity;
2. a characterization records measured conversion or response values;
3. a correction assignment approves which source may satisfy a signal
   requirement.

A certificate may support both the first and second records, but the operator
confirms each stage. Recording calibration does not create characterization or
correction data. A characterization whose source is a calibration certificate
does not create a calibration event.

## Compatibility And Storage

- station migrations `0003_station_material_requirements.sql` and
  `0004_station_qualified_revision_derivation.sql` are additive;
- immutable v1/v2 station definitions and checksums remain readable;
- a v2 revision changes shape only by explicitly deriving a new v3 draft;
- existing fleet assets, calibrations, characterizations, correction
  assignments, audit and outbox records remain in their owning stores;
- every Local Agent JSON success and error response now declares
  `application/json; charset=utf-8`.

## CA-001 Acceptance

The real-agent scenario proves that CA-001 can have an active cable-loss
correction while calibration and location remain missing. It can be saved as an
exact setup requirement but cannot be assigned or marked ready. Moving it to
`labo CEM` removes only the location blocker. Recording the conforming EMITECH
calibration removes the calibration blocker without altering the existing
characterization or correction assignment. The exact requirement remains
unchanged and the final station can then become operationally ready.

## Operator Surfaces

- LAB CONSOLE exposes the three role modes, logical ports, candidate evidence,
  qualified/ready lifecycle, first-class calibration and staged certificate
  values.
- Python and Qt consume v2/v3 requirements, assignments, readiness and
  calibration projections from the Rust Local Agent. They do not implement an
  independent matcher.

## Limitations

This release does not control instruments, acquire samples, perform FFT or
time-domain processing, apply corrections at runtime, generate final reports,
authenticate users or synchronize distributed laboratories. Post-start material
replacement remains future execution-domain work. The production build still
reports the existing advisory for a JavaScript chunk above 500 kB. `npm ci`
also reports five high-severity dependency advisories; no forced dependency
upgrade was applied inside this release because it requires a separate,
validated dependency-maintenance pass.
