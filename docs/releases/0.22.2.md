# EMC Locus 0.22.2

Release date: 2026-08-05

## Purpose

This release connects reusable test intent, reusable measurement topology and
one dated laboratory realization. An engineer can define a typed CEM method,
map its functional roles into signal and feedback paths, preview the resulting
execution contract and then derive an immutable dated configuration from the
existing 0.22.1 preparation engine.

## Domain Contracts

- `emc-locus.test-method-definition.v2` adds typed variable semantics,
  functional roles, deterministic expressions, hierarchical finite procedure,
  sub-ranges, modulation, classified limits and typed post-processing.
- `emc-locus.measurement-system-template-definition.v1` adds revisioned role
  nodes, logical ports, typed paths, correction points and regulation loops.
- `emc-locus.regulation-profile-definition.v1` adds versioned open-loop,
  closed-loop and monitor-only strategies with stepped control and protection
  settings.
- `emc-locus.execution-configuration.v1` pins exact method, topology and
  station revisions plus the physical assignments produced by planned-test
  preparation.

The Rust core owns all graph, expression, unit, loop, mapping and compatibility
validation. TypeScript, Python and Qt consume projections and do not implement
parallel business-rule engines.

## Workflow And UX

LAB CONSOLE replaces the schema-tab method editor with a guided operator
workflow, editable method hierarchy, accessible topology graph and textual
fallback, explicit graph layers, regulation preview, hierarchical sequence,
bounded sub-range preview and explainable execution-plan compilation. Empty
states explain prerequisites and secondary source failures remain local.

The operator categories `emc_receiver` and `spectrum_analyzer` resolve to
`frequency_selective_measurement_instruments` for new projections while all
historical model revisions and category references remain unchanged.

Python and Qt add read projections for method revisions, system templates,
regulation profiles, execution-plan previews and dated mappings.

## Persistence And Compatibility

Additive migrations are:

- `test_definitions/0006_method_workflow_v2.sql`;
- `projects/0009_execution_configurations.sql`;
- `equipment/0010_frequency_selective_category_alias.sql`.

Historical method v1, station v2/v3 and planned-preparation v1 records remain
readable with unchanged checksums. A method v1 evolves only through the audited
`successor-0.22.2` command. It preserves identity and unresolved migration
evidence, creates a draft and never guesses topology or approval.

## Runtime Boundary

0.22.2 defines, validates, previews and persists an execution contract. It does
not control instruments, acquire samples, execute FFT, apply corrections to
measurement data, generate final reports, authenticate users or synchronize
distributed laboratories. A compiled plan is not evidence that a test ran.
