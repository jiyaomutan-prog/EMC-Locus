The Playwright runner now namespaces the 0.22.2 preparation fixture and tracks
the current isolated agent PID across successive restart scenarios. This
removes order dependence without weakening schedule conflicts or preparation
readiness. The generated LAB CONSOLE bundle retains a 642.51 kB main-chunk
advisory, and `npm ci` reports one high-severity dependency advisory. Both are
recorded as follow-up debt rather than hidden by an unreviewed forced upgrade.

PR CI and exact merge-head CI are appended after GitHub has evaluated those
immutable commits.

The first PR run, `CI #142` (run ID `31007245067`), exposed one
cross-checkout reproducibility defect at the versioned-dist step. The SVG
sprite had 26 LF line endings locally but was checked out with 26 CRLF line
endings by the Windows runner, changing its Vite content hash and dependent
chunk names. `.gitattributes` now enforces LF for LAB CONSOLE SVG sources. A
fresh production build reproduces the committed dist byte-for-byte.

## Boundaries

No driver execution, acquisition, FFT implementation, runtime correction,
final reporting, authentication, distributed synchronization or parallel
physical-assignment engine was introduced. Historical immutable checksums are
not recalculated.

## Mandatory Self-review

- dated physical assignments still come only from planned-test preparation;
- graph, expression, unit and compatibility validation remains authoritative
  in Rust, with no TypeScript or Python validator fork;
- the constrained expression model cannot execute JavaScript, Python or shell;
- safety limits and final verdict rules remain distinct, with no hidden bypass;
- exact-asset requirements cannot be silently substituted;
- approved historical revisions and checksums are not rewritten;
- normal operator views use French labels, with JSON and internal values kept
  under technical details;
- methods contain no dated asset assignment and reusable systems require no
  location;
- dated configurations pin exact method, topology and station revisions;
- closed-loop regulation requires an explicit reachable feedback path;
- procedure loops require finite bounds;
- unsupported runtime operations are returned as warnings and are not
  presented as executed;
- empty states and unavailable secondary sources keep prerequisites and retry
  actions visible;
- `data/local-agent` has no diff.
