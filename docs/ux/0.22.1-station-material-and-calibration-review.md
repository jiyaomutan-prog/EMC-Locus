# 0.22.1 Station Material And Calibration UX Review

Review date: 2026-07-31

## Operator Questions

The reviewed workflow answers four separate questions:

1. What kind of material does the setup require?
2. Which serialized asset is selected for the planned use?
3. Is that selection compatible with the design requirement?
4. Is it operationally eligible for this date, place and quality mode?

The interface never uses an exact requirement as a safety or metrology bypass.
Candidate cards expose corrections, calibration, location and overall
eligibility independently. The correction panel uses the scoped wording
**Corrections requises disponibles** and never claims that the complete test is
ready.

## Calibration Review

**Enregistrer un étalonnage** is visually and semantically distinct from
**Ajouter une caractérisation**. Required certificate fields are visible. The
history presents operator vocabulary rather than raw JSON. After save, the
current dossier remains selected while status and history refresh separately.
A secondary history failure leaves the station and metrology context visible.

The follow-up action **Ajouter des valeurs de correction issues de ce
certificat** prefills certificate evidence but still requires explicit measured
values and does not create a correction assignment.

## Screenshot Evidence

The explicit refresh guard requires both
`EMC_LOCUS_REFRESH_RELEASE_SCREENSHOTS=1` and
`EMC_LOCUS_RELEASE_SCREENSHOT_VERSION=0.22.1`. Ordinary Playwright runs do not
write release evidence. Historical images from 0.18.0 through 0.22.0 are not
modified.

The 19 reviewed PNG files cover:

- role type selection and hierarchical category role;
- capability role with detector and driver constraints;
- exact blocked and exact eligible assets;
- saved exact requirement;
- compatible-but-unavailable and incompatible candidate groups;
- qualified and operationally ready setups;
- planned preparation with physical assignments and port mappings;
- calibration form and history;
- missing versus valid calibration while corrections remain available;
- scoped correction verdict wording;
- immutable station v2 compatibility and explicit v3 derivation.

Both required viewport sizes, 1440 x 900 and 1280 x 720, are represented. The
review checked navigation, modal bounds, form labels, action explanations,
status contrast, horizontal overflow and persistence after navigation/restart.

## Findings

- No raw JSON or technical database ID is visible in normal operator mode.
- Blocked exact assets stay visible with causes and next actions.
- Disabled assignment actions explain why they cannot proceed.
- Deferred station roles and method roles are intersected by agent evidence;
  incompatible station assignments are not offered.
- Existing physical port mappings are preloaded in planned-test preparation.
- Station v2 remains readable and unchanged.

No blocking visual defect remains. The dense station and preparation views are
deliberately work-focused; future optimization should split the production
JavaScript bundle without changing this workflow.
