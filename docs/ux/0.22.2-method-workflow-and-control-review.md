# 0.22.2 Method Workflow And Control UX Review

Review date: 2026-08-05

## Operator Mental Model

The reviewed LAB CONSOLE workflow keeps three decisions separate:

1. **Méthode**: what the test must achieve, observe and decide;
2. **Système de mesure**: how logical functions, ports, signals and feedback are
   connected without choosing serial numbers;
3. **Préparation datée**: where and when the test occurs and which physical
   assets satisfy each role.

The method authoring surface is a guided sequence with completion and blocking
states. Internal JSON is confined to technical details. The normal interface
uses French labels for variable semantics, role categories, edge kinds and
lifecycle states.

## Topology And Regulation

The topology view uses original monochrome schematic icons, stable node sizes,
explicit port-to-port connection commands and layer controls for physical
signals, regulation, command/data and all edges. Selecting a node opens a
structured inspector for role mapping and logical ports. The connection table
contains the same information as the visual graph and remains keyboard and
screen-reader accessible.

The regulation workspace combines a stepped preview, editable values, a
language summary and validation. Closed-loop omissions remain visible and are
rejected by the Rust agent. A feedback edge has a distinct visual and textual
meaning from excitation, monitoring and command paths.

## Empty And Failure States

- An empty repository explains that a method or approved predecessor is the
  first prerequisite and provides the relevant action.
- System topology can be designed before the physical equipment fleet exists.
- A hierarchy-source failure produces a targeted notice while the method list
  remains readable.
- Preview and secondary data failures do not replace the primary workspace.
- Read-only approved revisions explain why authoring actions are unavailable.

## Findings

- No physical asset, location or calibration state appears in reusable method
  or topology definitions.
- The graph is not canvas-only and can be operated by keyboard.
- Unsaved draft history supports undo and redo; immutable revisions are
  visibly read-only.
- Unsupported FFT and correction execution are labelled as future runtime
  capabilities, not represented as completed measurements.
- At 1280 x 720, navigation, graph controls, inspector and primary commands
  remain reachable without horizontal page scrolling.

No blocking UX defect remains in the 0.22.2 contract-definition workflow.
