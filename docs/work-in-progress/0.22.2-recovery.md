## Confirmed overlaps and gaps

- Method `instrumentation_chain` and station `material_requirements` both describe resource needs.
- Method slots are flat and less expressive than station v3 requirements.
- Station v3 correctly separates requirements from physical assignments, but the reusable logical topology is mixed with dated location and planned-use context.
- Planned preparation already owns dated revision pins and physical assignments; it must remain the single operational assignment path.
- Method sequence, limits and post-processing are typed but too shallow for hierarchical procedures, regulation, classified limits and an explainable dry-run plan.
- LAB CONSOLE exposes schema-shaped tabs and several raw internal enum values.
- The method library is flat and has no editable hierarchy.
- No first-class measurement-system template or regulation-profile aggregate exists.
- Python and Qt expose station views but no authoritative method/topology/execution-plan read projection.

## Target architecture

1. A method v2 owns reusable intent: typed variables, functional roles, procedure,
   sub-ranges, modulation, limits, post-processing and references to reusable
   topology/regulation revisions.
2. A measurement-system-template v1 owns reusable role nodes, logical ports,
   typed edges, correction points and feedback-loop mappings without date,
   location or physical asset.
3. A dated execution-configuration v1 extends planned preparation and pins the
   approved method revision, topology revision, parameter values and exact
   station/material snapshots.
4. The Rust Local Agent validates graphs, expressions, units, role mapping and
   compiles the read-only execution plan.
5. Station v2/v3 and preparation v1 remain readable. No historical checksum is
   recalculated.

## Compatibility strategy

- Add successor schemas; never edit approved v1 method definitions.
- Keep existing method routes for the revision aggregate and add explicit
  successor derivation plus dedicated hierarchy/topology/preview routes.
- Preserve station v2/v3 as dated operational realizations.
- Map legacy instrumentation slots to v2 functional roles only through an
  audited successor-draft command.
- Preserve unconvertible legacy fields as migration evidence requiring review.
- Add category aliases instead of rewriting immutable model revisions.
- No dual physical-assignment engine and no client-side compatibility engine.
