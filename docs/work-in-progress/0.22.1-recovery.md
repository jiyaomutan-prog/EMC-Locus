## Confirmed Defects

1. Station definition v2 stores only immediate physical asset bindings. The
   candidate endpoint filters design choices through current operational
   eligibility, so an exact but blocked asset cannot be expressed as a setup
   requirement.
2. LAB CONSOLE labels a characterization source as a calibration certificate,
   but exposes no command for the authoritative calibration event already
   supported by the Local Agent. A characterization therefore appears more
   powerful than it is while calibration correctly remains missing.
3. JSON responses use `application/json` without an explicit UTF-8 charset,
   which leaves Windows PowerShell 5.1 free to decode French payloads
   incorrectly.

The detailed pre-change audit is in
`docs/domain/station-material-requirements-0.22.1-audit.md`.

## Architecture Decisions

- Preserve immutable v1 and v2 station revisions and their canonical JSON and
  checksums.
- Introduce
  `emc-locus.station-measurement-setup-definition.v3` as a typed core
  contract.
- Separate `material_requirements`, physical `material_assignments`, and
  contextual operational readiness.
- Use logical ports in requirements and snapshot exact physical port mappings
  only after an immutable model revision and physical asset are selected.
- Match cross-model requirements by stable capability kind and trusted units;
  model-local capability IDs are supporting evidence only.
- Replace the ambiguous lifecycle with `draft`, `qualified`, `ready`, and
  `superseded` for v3 while continuing to read historical v2 `ready`
  revisions.
- Keep matching and readiness authoritative in Rust. TypeScript and Python
  consume projections and never implement a parallel matcher.
- Reuse `calibration_events` and the existing metrology service. The release
  adds a first-class LAB CONSOLE action and client models, not a second
  calibration store.
- Keep calibration events, characterizations, and correction assignments as
  three separate evidence boundaries. No operation implies another.
- Declare all Local Agent JSON success and error responses as
  `application/json; charset=utf-8`.

## Compatibility and Migrations

- Add station migration `0003` for the v3 contract metadata and any required
  lifecycle constraints/indexes without editing migrations 0001 or 0002.
- Preserve every station v2 definition and checksum byte-for-byte.
- Upgrade only a derived editable draft through an explicit audited command;
  never mutate the source v2 revision.
- No metrology schema migration is planned initially because the existing
  `calibration_events` model already carries the required decision, dates,
  as-found/as-left states, uncertainty, traceability, document manifest,
  actor evidence, audit, outbox, and idempotence contract.
- Validate fresh storage, populated 0.22.0 storage, migration replay, restart,
  and v2-to-v3 derivation before release.
